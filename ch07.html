2부 패턴 레퍼런스 · 제 7장

A 공통 서비스

모델·데이터·문서 형식·도구 인터페이스처럼 업무 부품이 딛고 서는 기반을 다룬다. 공통 서비스는 한 번 만들어 여럿이 나눠 쓸 때 제값을 한다.

이 장에서 얻을 것
  • A 계층 19개 항목을 네 묶음으로 나눠 각자의 자리를 안다
  • 환경 조건으로 모델 서빙 변형(A2.0~A2.6)을 고른다
  • 공통 서비스를 새로 만들기 전에 범정부 Provider부터 찾는 순서를 익힌다
  • PAX 564건에서 A 계층이 어떻게 쓰였는지 읽는다

세 부서가 같은 모델을 세 번 계약할 때

모델 호출에 한 달 얼마를 쓰는가. 이 물음에 한 숫자로 답하지 못하는 기관이라면 사정은 대개 이렇다. 민원 부서는 상담 챗봇을, 기획 부서는 보고서 초안 도구를, 총무 부서는 회의록 요약기를 거의 같은 시기에 만들었다. 세 과제가 상용 모델 API 키를 따로 받았고, 같은 규정집을 각자의 벡터DB에 넣었다. 공급사가 요금제를 바꾸거나 서비스가 하루 멈추면 셋이 한꺼번에 흔들린다.

카탈로그는 이 상태를 X3부서마다 챗봇이라 부르고, 빠진 부품으로 모델 서빙 계층과 공공 API 제공자를 지목한다. 둘 다 A 계층, 곧 공통 서비스(Platform Services)에 속한다. A 부품은 업무 컴포넌트가 딛는 기반이다. B 주 부품은 과제마다 하나지만 A 부품은 여러 개가 붙는다. 이 부품들은 기관이나 범정부 수준에 한 번 두고 여러 과제가 나눠 쓰는 Provider 방식일 때 제값을 한다.

GoF의 세 범주에 대면 A 계층은 생성(Creational) 패턴의 자리에 있다. 업무 부품이 쓸 모델·데이터·서식을 대신 만들어 건네준다. AX 성숙도로 보면 A 계층은 Ready 관문과 짝을 이룬다. 데이터 기준선(A1데이터 자산 서비스)과 계약된 데이터 결합(A4데이터 연계 서비스)이 갖춰져야 AI-Ready로 인정되고, A 부품만 있는 과제는 Ready를 넘지 못한다. 업무 흐름을 바꾸는 일은 B 부품이 하고, 공통 서비스는 그 부품이 올라설 땅을 고른다.

핵심 요약
  • X3 부서마다 챗봇은 A2·A3 Provider가 빠진 결과다.
  • A 부품만으로는 AX 단계가 Ready에 머문다. 업무 흐름은 B 부품이 바꾼다.

네 묶음으로 본 A 계층

A 계층의 19개 항목은 번호 순서로 읽으면 성격이 뒤섞이고, 하는 일로 묶으면 네 묶음이 된다(그림 7.1). 데이터 기반 묶음에서는 A1데이터 자산 서비스가 기관 안의 기록을 정제해 기준선을 만들고, A4데이터 연계 서비스가 다른 기관 데이터를 계약으로 결합하며, A6지식그래프 서비스가 규정과 개념 사이의 관계를 명시한다.

모델 서빙 묶음의 중심은 A2다. v0.7에서 A2는 모델 게이트웨이에서 모델 서빙 계층으로 이름을 넓혔고(R13), 그 아래에 일곱 변형을 둔다. 상용 API, 주권형 온프레미스, 튜닝형, 내부망 프록시 같은 LLM 변형에 더해 비LLM 학습 모델(A2.5), 벤더 블랙박스(A2.6), 모델 미상(A2.0)이 들어왔다. 현장 기기에서 추론하는 A5엣지 추론 런타임도 모델이 도는 자리라 이 묶음에 둔다.

셋째 묶음은 Provider와 제작 환경이다. A3공공 API 제공자는 범정부 AI 공통기반, 공공데이터포털, 공공 깃랩처럼 정부가 운영하는 기반을 가져다 쓰는 자리이고, A7자체 제작 환경은 기관 인력이 AI 코딩 도구로 직접 만드는 자리다. A9업무 규범 스킬은 보고서 구조·문체·검증 절차를 모델 중립 스킬로 묶어 어떤 코딩 에이전트에서든 다시 쓰게 한다.

남은 묶음은 어댑터다. A8MCP 서버·호스트가 공공 API와 업무 시스템을 에이전트가 부르는 도구로 감싸고, A10문서 형식 어댑터가 HWP·HWPX·엑셀을 읽고 쓴다. A12접근성·모달리티 어댑터는 A10과 대칭인 사람 쪽 어댑터로, 음성·다국어·쉬운 언어를 맡는다. A11액추에이션·현장 통지 어댑터는 판정을 경광등이나 알림톡으로 내보내며, R14에 따라 물리 설비를 움직이는 A11a(P2a)와 소프트웨어 통지를 보내는 A11b로 나뉜다.

Gulli(2025) 10장은 기존 서비스를 MCP 도구로 감싸면 다시 짜지 않고 재사용하게 된다고 하면서, 돌려주는 데이터가 에이전트가 읽을 형태여야 한다는 단서를 붙인다. 공공 문서에서 그 형태를 만드는 부품이 A10이다. 16장의 자원 인지 최적화는 쉬운 질의를 값싼 모델로 보내고 장애 때 대체 모델로 넘기는 방식이라 A2의 라우팅·폴백에 해당한다. 부록 A의 프롬프트 기법은 A9와, 부록 G의 코딩 에이전트는 A7과 겹친다. 데이터 기반(A1·A4), 범정부 Provider(A3), 문서 형식 어댑터(A10)에 대응하는 장은 없으며, 이 자리를 공공 카탈로그가 채웠다.

모델 서빙 변형을 고르는 순서

A 계층에서 판단이 가장 자주 갈리는 곳은 A2다. 어떤 모델을 쓰느냐보다 모델이 어디서 어떻게 서빙되느냐가 조립을 바꾸기 때문이다. 같은 지식 접지 상담이라도 인터넷망에서 공개 문서를 다루면 상용 API로 충분하지만, 행정망에서 민감 등급 문서를 다루면 내부망 프록시 없이는 조립이 성립하지 않는다. 카탈로그 §5의 데이터 등급 축이 이것을 못 박는다. E5가 S 이상이면 해외 상용 API를 직접 부를 수 없다.

그림 7.2의 질문 가운데 무게가 가장 큰 것은 첫 질문이다. 런타임에 모델을 한 번도 부르지 않는 도구라면 A2는 필요 없고, 그 도구는 B0 결정적 도구다. 모델을 부른다면 먼저 모델의 정체를 묻고(자체 학습인가, 벤더 내장인가, 아직 미상인가, 재학습했는가), 다음으로 망과 등급을 묻는다. 튜닝형(A2.3)은 흐름도 한가운데 있지만 진행 경로(§7.2)에서는 열한 단계 중 마지막이다. 평가 세트로 잰 격차가 접지와 스킬로도 메워지지 않을 때 가는 길이다.

변형이 무엇이든 A2를 한 겹 두는 이유는 같다. 업무 부품이 벤더 API를 직접 부르면 대체 모델을 끼울 자리가 없다. 카탈로그가 서빙 계층을 C7폴백 스위치의 전제로 보는 까닭이다. C7이 없으면 Native 관문을 넘지 못한다. 폐쇄망 과제라면 로컬 대체 모델(A2.2)이 사실상 유일한 자동 전환 경로다.

흔한 실수

모델부터 고르고 공통 서비스는 나중에 찾는 경우가 가장 많다. 적용 절차(§7.1)의 두 번째 단계는 반대로 말한다. 데이터 자산·모델 서빙·문서 어댑터는 새로 만들기 전에 범정부 AI 공통기반, 공공 깃랩, 공공데이터 MCP에서 먼저 찾고, 없을 때만 만들며, 만들었으면 레지스트리에 올린다.

이웃 계층과의 경계

A 계층은 네 이웃과 맞닿아 있다(그림 7.3). 위로는 B 계층이 A에 의존한다. 주 부품은 하나지만 A 부품은 여럿이고, 여러 과제가 같은 Provider를 나눠 쓸수록 조립이 가벼워진다. 경계가 헷갈리는 곳은 자체 제작 환경이다. A7자체 제작 환경은 도구를 만드는 자리이고, 그렇게 만든 규칙 기반 도구는 B 계층의 B0결정적 도구다. MCP 서버 하나만 공개한 사례도 같은 식으로 읽는다. 서버 자체는 B0(MCP 도구 제공 변형)이고, 도구 인터페이스로서 A8MCP 서버·호스트를 함께 태그한다.

옆으로는 S 계층과 자리를 나눠 쓴다. S1AI 게이트웨이·단일 진입점은 A2와 같은 자리에 있다. A2가 모델 교체·라우팅·캐싱을 맡는다면 S1은 같은 진입점에서 인증·요청 상한·감사 기록·비용 상한을 건다. 부서별 API 키로 상용 모델을 직접 부르는 구조는 A2의 부재이면서 S1의 부재다. 반대편에는 E 환경 조건이 있다. E는 조립도의 전제이고 부품 목록에는 오르지 않는다. 온프레미스는 E1·E2의 값이고, 그 값을 채우는 부품이 A2.2주권형 온프레미스다. MCP는 부품(A8)이면서 실행 형태 조건(E3)이기도 하다. 아래로는 C 운영 부품이 A에 꽂힌다. 폴백은 모델 서빙 계층에 대체 모델을 등록하는 방식으로 붙고, C9평가 세트·회귀시험은 데이터 자산에서 정답을 얻는다.

01문제

업무 기록은 시스템·부서·형식마다 흩어져 있고 중복·결측·정의 불일치가 섞여 있다. 모델부터 고르고 데이터를 나중에 맞추면 실데이터 없이 시연만 되는 데모웨어(X6)가 되고, 과제마다 따로 정제하면 같은 가공을 기관 안에서 되풀이한다. PAX가 AI-Ready를 판정할 때 보는 요소(데이터·권한·책임·기준선)도 이 부품에서 갖춰진다.

맥락. 학습 모델(A2.5·B2), 지식 접지(B3)의 코퍼스, 평가 세트(C9)의 정답 출처가 필요한 과제라면 모두 이 부품을 쓴다. 서비스 유형 5a·9·10·11에서는 필수 기반이다. 비LLM 규칙 기반 대민 안내에서는 A2를 거치지 않고 결정론 조회의 대상이 된다(R21).

지표 표준화형여러 자료원의 지표를 도메인별로 표준화하고 정의·단위·분모·결측·원본 링크를 메타데이터로 관리한다.
자동 피처 파이프라인형수집→정제→파생 변수 생성→자동 검증→담당자 승인을 주기 실행하고 승인만 사람에게 남긴다.

03적용

  1. 기준선을 쓸 부품(B2·B3·C9 등)과 용도를 먼저 정하고, 데이터 등급(E5)과 배포망(E1)을 판정한다.
  2. 원천 목록을 만들고 중복·결측·정의 불일치를 파악해 정제 기준을 수치로 정한다('N건→M건' 기록).
  3. 라벨링 기준·인력·검수 절차를 정하고 학습/검증/평가 분할 규칙을 둔다.
  4. 변수·테이블·인터페이스 정의서(데이터 사전)를 작성해 소비 부품이 같은 정의를 쓰게 한다.
  5. 기준선을 버전으로 고정하고 C9 정답 출처와 C6 재학습 입력으로 연결한다.
  6. 기관 공통 기준선으로 쓸 수 있으면 레지스트리에 올려 다른 과제가 재사용하게 한다(§7.1 2단계).

점검 질문

  • 정제 전후 규모와 정제 기준이 기록되어 있는가
  • 데이터 사전(정의·단위·출처)이 있는가
  • 기준선에 버전이 있고 평가용 분할이 학습용과 분리되어 있는가
  • 데이터 등급(E5)에 맞는 가명·비식별 처리가 적용되었는가

환경 조건. E5 등급이 S 이상이면 가명·비식별 처리 뒤에 기준선을 만든다. E1이 폐쇄망이면 기준선도 망 안에 두고, 외부 모델(A2.1)로 넘길 때는 C5 비식별을 앞에 둔다.

적용 노트

공공데이터를 정제해 기준선으로 고정하는 일은 개인 개발 도구에서도 흔하다. PAX 564건 태깅에서 A1이 붙은 사례는 115건이다. 태깅 근거로는 'N건→M건 정제'처럼 규모와 기준을 함께 적은 서술이 가장 확실하다.

기준선을 만들 때 학습용과 평가용 분할을 같은 날 고정해 둔다. 평가용 분할을 나중에 고르면 C9 결과가 학습 데이터와 겹쳐 실제보다 좋게 나온다. 데이터 사전은 소비 부품이 바뀌어도 남는 문서이므로, 표준을 갖추면 같은 체계를 쓰는 다른 기관에 그대로 넘긴다.

다른 기관의 데이터가 섞이면 A4데이터 연계 서비스를 따로 태그해 계약과 키 매핑을 드러낸다. 결합한 뒤 정제까지 했다면 두 부품을 모두 기록한다.

위기가구 예측 시범, 모델보다 먼저 막힌 곳

복지정책과는 위기가구를 먼저 찾아내는 예측 모델을 시범 운영하기로 했다. 외부 업체는 첫 회의에서 모델 사양보다 학습용 데이터를 먼저 보자고 했다. 기록은 사례관리 시스템, 상담 기록 엑셀 세 종류, 방문 메모로 나뉘어 있었다. 같은 가구가 서로 다른 번호로 여러 번 등장했고, 엑셀마다 '가구'의 정의도 달랐다.

마침 같은 기록으로 복지 안내 상담도 준비 중이었다. 정보통신과 AX팀은 두 과제가 각자 정제를 맡으면 같은 일을 두 번 하고 결과도 서로 맞지 않는다고 보고, 먼저 A1데이터 자산 서비스를 세우자고 제안했다. 원천 목록을 만들고 중복·결측 기준을 수치로 정한 뒤, 정제 전후 규모를 기록하고 가구·세대·위기 사유의 정의를 데이터 사전에 고정했다. 학습·검증·평가 분할도 이때 정했다.

기준선에 버전을 붙이자 두 과제가 같은 판을 쓰게 되었다. 예측 모델은 v1 기준선으로 학습해 A2.5비LLM 학습 모델로 서빙했고, 평가용 분할은 C9평가 세트·회귀시험의 정답 출처가 되었다. 복지 안내 상담(B3지식 접지 상담)도 같은 사전의 용어를 썼다. 다음 분기에 재학습할 때는 C6환류 파이프라인이 v2 기준선을 입력으로 받는다.

민감 등급 기록이라 가명 처리를 먼저 거쳤고, 기준선은 행정망 안에만 둔다. 회의록에 남은 조립은 A1 → A2.5 → B2 → C1 · A1 → C9 · A1 → B3 · A1 → C6 → A2.5 한 줄이었다. 그 한 줄에 이르기까지 모델 이야기는 거의 나오지 않았다.

01문제

업무 코드에 특정 모델 API가 박혀 있으면 모델 교체·장애 대응·비용 통제·민감정보 반출 통제를 걸 자리가 없다. 상용 API를 업무 코드에서 직접 부르면 C7 폴백을 끼울 자리부터 없다(X4). 또 v0.5까지 A2는 LLM 어휘만 있어 비LLM 자체 학습 모델·벤더 내장 모델·모델 미상 사례가 들어갈 곳이 없었고, 이 공백이 태깅 피드백으로 돌아왔다(R13).

02해법

업무 부품과 모델 사이에 서빙 계층을 두고 모든 호출을 이 층으로 보낸다. 계층은 모델 버전을 고정하고 사용량·지연 로그를 C4로 넘기며, 대체 모델을 함께 등록해 C7이 전환할 자리를 만든다. 지능형 모델 라우팅(경량 모델이 복잡도를 보고 큰 모델로 넘김)·프롬프트 캐싱·동적 배칭은 모두 이 계층이 있어야 걸리는 비용 통제다. 하위 변형은 모델이 어디서 도는가로 고른다. 기관 밖 상용 API면 A2.1(행정망·민감 등급이면 A2.4), 오픈웨이트를 기관 안에서 돌리면 A2.2, 재학습했으면 A2.3, 비LLM 자체 학습이면 A2.5, 장비·상용 제품에 내장돼 있으면 A2.6, 알 수 없거나 이용자가 가져오면 A2.0이다.

A2.6모델 서빙 · 벤더 블랙박스벤더 블랙박스장비·상용 제품에 내장돼 있어 기관이 모델을 보지도 바꾸지도 못한다.

03적용

  1. E1 배포망·E2 모델 의존·E5 데이터 등급을 먼저 기록해 허용되는 변형을 좁힌다(E1 폐쇄망인데 상용 API면 조립 오류).
  2. 업무 코드가 모델 SDK를 직접 부르지 않도록 서빙 계층 인터페이스를 정하고 주 경로 변형을 고른다.
  3. 모델·프롬프트·설정 조합을 릴리스처럼 버전으로 고정하고 C9 평가 세트로 교체 전후를 비교한다.
  4. 대체 모델을 같은 계층에 등록해 C7 전환 경로를 만든다.
  5. 사용량·지연·모델 버전 로그를 C4로 보내고, 비용이 문제면 라우팅·캐싱·배칭을 켠다.

점검 질문

  • 업무 코드가 특정 모델 API를 직접 호출하지 않는가
  • 모델 버전이 고정·기록되는가
  • 대체 모델 또는 대체 경로가 계층에 등록되어 있는가
  • 선택한 변형이 E1·E5 조건과 모순되지 않는가

환경 조건. E1 폐쇄망이면 A2.2·A2.4·A2.5만 가능하고 C7 경로도 '수동 전환·로컬 모델'로 제한된다. E5가 S 이상이면 해외 상용 API 직접 호출은 A2.4 없이는 불가하다. E2가 모델 중립(BYO)이면 A9 스킬로 규범을 모델 밖에 두어 모델 교체 가능성 자체를 C7로 삼는다.

적용 노트

A2는 부모 항목이라 태깅에서는 직접 쓰지 않고 E2 값에 맞는 하위 변형(A2.0~A2.6)을 하나 이상 기록한다(R13). 조립도에서 업무 코드가 서빙 계층 없이 모델을 부르는 자리는 빈칸으로 그려 둔다. 그러면 C7 결손이 바로 보인다.

하위 변형은 모델이 어디서 도는가로 고른다. 기관 밖 상용 API면 A2.1, 행정망·민감 등급이면 A2.4, 오픈웨이트를 기관 안에서 돌리면 A2.2, 재학습했으면 A2.3, 비LLM 자체 학습이면 A2.5, 제품 내장이면 A2.6, 알 수 없거나 이용자가 가져오면 A2.0이다. 한 계층 안에 여러 변형이 함께 등록되는 것이 보통이다.

Gulli는 『Agentic Design Patterns』 16장에서 쉬운 질의는 값싸고 빠른 모델로, 어려운 질의는 강한 모델로 보내고 예산 안에서 대체 모델과 단계적 성능 저하를 미리 준비하라고 권한다. 이 책에서 그 라우팅과 폴백이 놓이는 자리가 서빙 계층이다. 계층이 없으면 라우팅 규칙을 업무 코드마다 따로 심어야 한다.

계층을 부서마다 만들면 그 자체가 또 하나의 난립이 된다. 기관 공통으로 한 번 두고, 범정부 공통기반이 있으면 A3공공 API 제공자로 소비한다.

04영향

얻는 것

  • 모델 교체와 C7 폴백이 가능해짐
  • 라우팅·캐싱으로 비용 통제
  • 버전 고정으로 회귀시험 가능
  • 민감정보 반출 통제 지점 확보

치르는 대가

  • 추가 계층의 운영·유지 비용
  • 변형별 인프라(GPU·프록시) 비용
  • 계층 자체가 단일 장애점이 될 수 있음

이럴 때 쓴다

  • 업무 부품이 런타임에 모델을 한 번이라도 부를 때
  • 상용 API에 의존해 C7 폴백을 끼워야 할 때(E2 해외 상용 API)
  • 호출당 비용·지연을 관리해야 할 때(라우팅·캐싱)
  • 모델 업데이트 후 품질 회귀를 막아야 할 때(버전 고정 + C9)

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임에 모델을 부르지 않을 때
  • 모델이 아니라 도구·데이터를 감싸는 층이 필요할 때(A8·A3)

어느 화요일 오전, 민원여권과의 상담 챗봇, 기획예산과의 기안 도우미, 홍보 문안 도구가 거의 동시에 오류를 냈다. 세 도구는 각자 다른 업체가 만들었지만 모두 같은 상용 API를 업무 코드에서 직접 부르고 있었다. 장애는 두 시간 만에 풀렸지만, 그 두 시간 동안 세 도구가 넘어갈 경로는 없었다.

정보통신과 AX팀이 점검해 보니 문제는 장애 하나가 아니었다. 부서마다 API 키가 따로라 월 사용량을 합산할 수 없었고, 모델 버전도 기록되지 않아 지난달 답변 품질이 왜 바뀌었는지 설명할 수 없었다. 행정망 업무인데 민감한 본문이 어떤 경로로 나가는지 확인할 지점도 없었다. 전형적인 X4단일 모델 인질이자 X3부서마다 챗봇의 초기 증상이었다.

AX팀은 A2모델 서빙 계층을 기관 공통으로 하나 두기로 했다. 세 도구가 계층의 인터페이스만 부르게 바꾸고, 주 경로는 A2.4내부망 프록시를 거친 상용 모델, 대체 경로는 로컬 오픈웨이트 모델 서버(A2.2주권형 온프레미스)로 등록했다. 모델·프롬프트·설정 조합은 버전으로 고정했고, 모델을 바꿀 때는 전후를 C9평가 세트·회귀시험으로 비교하기로 했다.

다음 장애 때는 C7폴백 스위치가 호출을 로컬 모델로 넘겼다. 상담 챗봇은 느려졌을 뿐 멈추지 않았다. 그날의 호출은 B3 → A2.4 → 상용 모델 · A2 → C4 · A2 → C7 → A2.2 · C9 → A2 배선을 그대로 따라 흘렀다.

  2. BYO 설계라면 허용 모델 조건(E1 배포망·E5 등급)을 README나 안내문에 명시한다.
  3. 업무 규범을 A9 스킬로 분리해 모델이 바뀌어도 같은 산출물이 나오게 한다.
  4. 기관 공식으로 전이하기 전에 모델을 확정해 A2.1~A2.6 중 하나로 재분류하고 C7 경로를 정한다.

점검 질문

  • 모델 미상임이 조립도와 태그에 명시되어 있는가
  • BYO라면 허용 데이터 등급이 이용자에게 안내되는가
  • 전이 전 모델 확정 계획이 있는가

환경 조건. E2 = LLM(모델 미상) 또는 모델 중립(BYO). E1 폐쇄망·E5 S 이상과의 적합성은 판정 불가로 남는다. §5 매트릭스에서 E2 BYO는 A9 스킬 배포가 필수이며 MIT·Apache 라이선스 명시가 전이 조건이다.

적용 노트

A2.0은 v0.7 문서 개정으로 추가되었고 태깅 스키마에는 아직 반영되지 않았다. 현재 태깅 파일에서는 E2 값('LLM(모델 미상)' 또는 '모델 중립(BYO)')으로만 남는다. PAX 564건 태깅에서 E2가 BYO인 사례는 90건이고, 그중 자체 제작 환경(A7)을 함께 쓴 사례가 30건이다.

미기재형과 BYO형은 다르게 다룬다. 미기재는 기록의 빈칸이므로 확정이 목표다. BYO는 설계 의도이므로 허용 조건(배포망·데이터 등급)을 README나 안내문에 적고 MIT·Apache 같은 라이선스를 명시해야 전이 조건을 갖춘다.

보도자료 도구는 어느 모델에서 도는가

홍보 업무를 겸하는 한 주무관이 코딩 에이전트로 보도자료 초안 도구를 만들어 부서에 나눠 주었다. 도구는 각자 구독한 코딩 에이전트에서 돌았고, 누가 어떤 모델을 쓰는지는 아무도 몰랐다. 정보통신과 AX팀이 기관 도구 목록을 정리하면서 이 도구의 모델 칸에 '상용 API'를 적으려다 멈췄다. 도구 설명 어디에도 모델명이 없었기 때문이다.

추정해 적으면 '행정망인데 상용 API'라는 경고가 뜨거나, 반대로 실제로는 해외 서비스로 나가는데 통과로 표시될 수 있었다. AX팀은 도구가 이용자 구독 모델에 얹히는 BYO 설계임을 확인하고, 모델 칸에 A2.0모델 미상을 적었다. 그다음 도구 안 프롬프트에 섞여 있던 보도자료 구조·문체·금지 표현을 A9업무 규범 스킬로 떼어 냈다. 어떤 모델에서 돌려도 같은 절차가 나오게 하려는 것이다.

도구 안내문에는 민감 등급 자료를 넣지 말라는 조건을 F7한계·신뢰도 안내로 적었다. 목록에는 A9 → B7 → A2.0 · F7 배선과 함께, 기관 공식 도구로 올리기 전에 모델명·호출 위치·데이터 흐름을 확인해 다른 변형으로 재분류한다는 과제를 올렸다.

모델 칸에 미상이라고 적어 둔 덕에, 이 도구가 왜 아직 부서 공유 단계에 머무는지는 누가 목록을 열어도 바로 보인다. AX팀은 같은 방식으로 기관 도구 목록 전체를 다시 훑었고, 모델 칸이 비어 있는 도구 네 개를 더 찾아냈다.

01문제

GPU·모델 운영 없이 성능 높은 모델을 바로 쓰게 되므로 많은 도구가 이 변형을 택한다. PAX 564건에서 해외 상용 API에 의존하는 사례는 64건이고, 그중 61건에 C7 대체 경로가 없다. 그러나 업무 코드가 API 하나를 직접 부르면 장애·단가 변경·모델 업데이트에 서비스 전체가 묶이고(X4), 행정망 본문이 기관 밖으로 나간다. PAX 564건 평가에서 복원력이 미확인인 사례는 468건(83%)이다.

02해법

업무 코드는 서빙 계층만 부르고, 서빙 계층이 상용 API를 호출한다. 행정망 본문이 나가는 경로 앞에는 C5 비식별 전처리를 두고, 대체 모델을 등록해 C7 폴백을 건다(§5 매트릭스 E2 해외 상용 API 행). 모델 버전을 고정하고 모델·프롬프트·설정 조합을 릴리스처럼 관리해 업데이트 전후를 C9로 비교한다. 비용이 문제면 라우팅·캐싱으로 큰 모델 호출을 줄인다. E5가 S 이상이면 이 변형 단독으로는 안 되고 A2.4 내부망 프록시를 거친다.

03적용

  1. 전송될 데이터의 등급(E5)을 판정하고, S 이상이면 A2.4로 방향을 바꾼다.
  2. 서빙 계층을 거쳐 호출하도록 구성하고 업무 코드의 직접 호출을 없앤다.
  3. 외부 전송 전 C5 비식별 전처리를 넣는다.
  4. 모델 버전을 고정하고 C9 평가 세트로 업데이트 전후를 비교하는 절차를 둔다.
  5. 대체 모델·규칙 축소·수동 전환 중 하나 이상을 C7 경로로 등록하고 한 번 실행해 본다.

점검 질문

  • 업무 코드가 상용 API를 직접 부르지 않는가
  • 외부로 나가는 프롬프트에서 무엇이 걸러지는지 답할 수 있는가
  • API 장애 시 대체 경로가 있는가
  • 모델 버전과 호출당 비용·지연이 기록되는가

환경 조건. E2 값은 해외 상용 API다. 조건-의존 검증에서는 E1 폐쇄망인데 A2 변형이 상용 API면 오류, E2 해외 상용 API인데 C7이 없으면 경고(§12). E5 S 이상이면 A2.4 필수. 유형 12에서 A2.1을 쓰면 C7 부재 경고를 유지한다(R22).

적용 노트

PAX 564건 태깅에서 A2.1은 88건으로 A2 변형 가운데 가장 많다. 4축 평가에서는 564건 가운데 468건(83%)이 복원력 미확인이다. 태깅에서 A2.1이 붙은 88건 가운데 C7을 함께 갖춘 사례는 9건뿐이다. C7 경로는 등록만 해서는 안 된다. 한 번 실행해 보기 전에는 실제로 동작하는지 모른다.

function calling이나 JSON Schema로 출력 형식을 고정해 부르는 구조화 호출도 이 변형에 속한다. 이때 판정은 규칙 엔진에 남기고 모델은 추출·초안만 맡긴다. 국산 상용 API도 망·등급 조건은 해외 API와 같이 따진다.

민원여권과는 인터넷 홈페이지에 여권 발급 절차를 안내하는 상담 도구를 시범 운영했다. 다루는 내용은 공개된 안내문뿐이어서 데이터 등급은 공개였고, 성능을 빨리 확인하려고 A2.1상용 API 호출을 택했다. 첫 달은 순조로웠다.

어느 월요일, 같은 질문에 대한 답변이 길어지고 말투가 달라졌다는 민원이 들어왔다. 업체가 모델을 갱신한 탓이었다. 업무 코드가 API를 직접 부르고 있어서 무엇이 언제 바뀌었는지는 기록에 없었다. 점검해 보니 시민이 상담 화면에 적어 넣은 개인 사정도 그대로 업체로 전송되고 있었다.

정보통신과 AX팀은 호출을 기관 A2모델 서빙 계층 뒤로 옮겼다. 전송 전에는 C5가드레일 필터가 이름·연락처를 지우게 했고, 모델·프롬프트·설정 조합은 버전으로 고정했다. 업데이트 소식이 오면 C9평가 세트·회귀시험의 질문 120개로 전후를 비교한 뒤에 바꾸기로 했다. 대체 경로로는 로컬 오픈웨이트 모델을 등록하고, C7폴백 스위치 전환을 한 번 실제로 돌려 보았다. 조립도에는 B3 → C5 → A2.1 · A2.1 → C7 → A2.2 · C9 → A2.1 경로가 그려졌다.

다음 모델 갱신 때는 회귀시험이 답변 길이 초과를 먼저 잡았다. AX팀은 프롬프트를 고친 뒤에야 새 버전으로 바꿨다. 같은 질문이 되풀이되는 안내 업무라 서빙 계층의 캐싱을 켜 두자 월 호출량도 눈에 띄게 줄었다.

01문제

행정망·폐쇄망 업무 문서와 민감자료는 외부 API로 보내지 못하므로 상용 모델을 쓸 길이 막힌다. PAX 564건 중 181건(약 3분의 1)은 네트워크 요구로 보면 로컬에서 완결되거나 폐쇄망에서 돈다. 문서가 PC 밖으로 나가면 안 된다는 조건도 이 변형으로 맞춘다(온나라 sAIde).

맥락. E1은 폐쇄망·행정망·로컬 PC, E2는 해외 오픈웨이트(로컬) 또는 국산 오픈웨이트, E5는 S 이상이다. 폐쇄망 B3·B6·B8, 유형 3(현장 폐쇄망 서버 추론), 유형 12 개발 코파일럿은 이 변형을 기본으로 쓴다.

적용 노트

PAX 564건 태깅에서 A2.2는 54건(약 10%)이다. 그런데 배포 환경을 보면 564건 가운데 169건(약 30%)이 로컬 PC나 폐쇄망에서 돈다. 로컬에서 도는 도구가 모두 로컬 모델을 쓰는 것은 아니라는 뜻이다. 공개 사례로는 온나라 사이드패널에서 로컬 모델로 요약해 문서가 PC 밖으로 나가지 않게 한 구성과, 공통기반 내부망에 오픈웨이트 모델을 직접 설치해 여러 부처에 제공한 사례가 있다.

폐쇄망에서는 C7 경로가 수동 전환과 다른 로컬 모델로 제한된다. 서버형과 로컬 PC형 중에서는 예상 이용자 수와 망 조건으로 고르고, 현장 기기 자체에서 돌아야 하면 A5엣지 추론 런타임을, 모델을 재학습했으면 A2.3튜닝형을 쓴다.

AX팀은 기관이 보유한 로컬 오픈웨이트 모델 서버를 쓰기로 했다. 먼저 C9평가 세트·회귀시험으로 지난해 설명서 요약 30건을 정답으로 삼아 상용 모델과 오픈웨이트 후보 두 종을 같은 조건에서 비교했다. 후보 하나가 상용 모델보다 점수는 조금 낮았지만 요약 기준을 넘었다. 모델과 패키지는 S11인제스천·공급망 검증을 거쳐 반입하고, 검색용 임베딩 모델도 함께 들여와 문서 색인까지 망 안에서 끝냈다.

서버가 한 대뿐이라는 점이 남은 걱정이었다. AX팀은 두 번째 후보 모델을 같은 서빙 계층에 등록해 C7폴백 스위치 경로로 두고, 서버 장애 때는 수작업 요약으로 돌아가는 절차를 적어 두었다.

요약 결과는 A10문서 형식 어댑터를 거쳐 기안 서식에 바로 들어간다. 요약 한 건이 지나는 길은 B1 → A2.2 (로컬 서버) → A10 → D8.2이고, 반입·평가·대체 경로까지 그리면 S11 → A2.2 · C9 → A2.2 · A2.2 → C7이 더해진다. 어느 구간도 망 밖으로 나가지 않는다. 상용 모델과의 점수 차이는 분기마다 같은 평가 세트로 다시 잰다. 더 나은 오픈웨이트 모델이 나오면 그 기록이 교체 근거가 된다.

§7.2 진행 경로의 마지막(11단계)에 둔다. 먼저 C9로 기준 성능을 재고, B3 접지와 A9 스킬로 개선한 뒤에도 남는 격차를 튜닝 목표로 정한다. A1 기준선에서 학습 데이터를 만들고 학습/검증/평가를 분리한다. 튜닝한 모델은 버전으로 관리해 이전 안정판으로 되돌릴 수 있게 하고(C7 변형), 재학습 주기는 C6로 연결한다. 갱신이 잦은 규정·기준은 가중치에 넣지 않고 A9·B3로 주입한다.

분류 코드 정확도, 튜닝 전에 잰 것

복지정책과는 상담 기록을 기관 고유의 서비스 분류 코드 80여 개로 나누는 도우미를 만들고 싶었다. 담당자는 '우리 코드는 특수하니 모델을 튜닝해야 한다'고 보고 업체 견적부터 받았다. 정보통신과 AX팀은 견적서를 보고 한 가지를 물었다. 지금 모델이 몇 퍼센트를 맞히는지 아느냐는 것이었다.

답이 없었다. AX팀은 C9평가 세트·회귀시험부터 만들었다. 지난해 상담 기록 400건에 사람이 붙인 코드를 정답으로 삼아 로컬 모델의 기준 성능을 쟀다. 다음으로 코드 설명서를 B3지식 접지 상담으로 검색하게 하고, 판정 기준을 A9업무 규범 스킬로 정리해 넣었다. 정확도는 크게 올랐지만 비슷한 코드 몇 쌍에서 오류가 남았다.

그제야 남은 격차를 튜닝 목표 수치로 정했다. A1데이터 자산 서비스의 기준선에서 학습·검증·평가 분할을 고정하고 로컬 모델에 경량 어댑터를 학습했다. 튜닝한 v2는 같은 평가 세트에서 기준을 넘은 뒤에 배포되었다. v1 안정판은 서빙 계층에 남겨 언제든 돌아갈 수 있게 했다. 최종 배선은 A1 → A2.3 → B1 → C1 · A9·B3 → B1 · C9 → A2.3 · C6 → A2.3이다.

튜닝 비용은 처음 받은 견적보다 크게 줄었다. 격차 대부분이 튜닝 전 단계에서 이미 풀렸기 때문이다. 분류 코드가 개정되면 가중치부터 다시 학습하지 않고 스킬과 설명서를 먼저 고친다.

01문제

행정망 업무에서 상용 모델 성능이 필요하지만 업무 PC가 인터넷에 직접 나갈 수 없고, 민감 등급 본문을 그대로 보낼 수도 없다. 로컬 모델(A2.2)은 성능·운영 부담이 크다. 남양주 AI-Agent(내부망 상용 AI)처럼 중계 계층으로 이 간극을 메우는 사례가 v0.3에서 변형으로 등재되었다.

맥락. E1은 행정망·내부망·사내망, E2는 상용 모델, E5는 S 이상이다. §5 매트릭스는 E5가 S 이상인 해외 상용 API 사용, 폐쇄망 B3, 행정망 B1(BYO 코딩 에이전트 불가)에 이 변형을 필수로 둔다.

  • 상용 모델 성능 vs 망 분리·반출 통제
  • 중계 계층 구축·운영 비용 vs 부서별 직접 호출의 난립(X3)
  • 통제 강화(로깅·차단) vs 지연 증가

02해법

업무 부품이 인터넷에 직접 나가지 않고 기관 AI 게이트웨이·클라우드 VPC 사설 엔드포인트·범정부 AI 공통기반을 경유해 상용 모델을 부르게 한다. 중계 계층에서 비식별(C5), 호출 기록(C4), 허용 모델 목록과 불용 모델 자동 제외를 적용한다. 같은 계층에 다중 모델 후보를 두면 C7 전환 자리가 되고, 인증·요청 상한·비용 상한을 걸면 S1 단일 진입점을 겸한다. 범정부 공통기반을 쓰면 A3 Provider 소비로도 기록한다.

03적용

  1. 업무 데이터 등급(E5)과 망 구성(E1)을 확인하고 중계 방식(사내 게이트웨이·사설 엔드포인트·공통기반)을 고른다.
  2. 업무 부품의 직접 호출을 모두 중계 계층 호출로 바꾼다.
  3. 중계 계층에 비식별·허용 모델 목록·호출 기록을 설정한다.
  4. 다중 모델 후보를 등록해 C7 전환 자리를 만들고, 인증·상한을 걸면 S1로도 기록한다.

  • 중계 호출이 기록되는가

환경 조건. E5가 S 이상이면 해외 상용 API는 A2.4를 거쳐야만 부른다(§5 E5). E1 폐쇄망의 B3에는 'A2 주권형 또는 내부망 프록시 + 로컬 임베딩', 행정망 B1에는 'A2 내부망 프록시(BYO 코딩 에이전트 불가)'가 붙는다. 유형 4도 행정망이면 내부망 프록시를 쓴다(§7.3).

적용 노트

PAX 564건 태깅에서 A2.4는 4건으로 드물다. PAX에는 개인이 만든 도구가 많아 기관 차원의 중계 계층이 등장할 기회가 적었다. 그러나 §5 매트릭스는 민감 등급 데이터로 해외 상용 API를 쓰거나 행정망 코파일럿(B1)을 둘 때 이 변형을 필수로 정한다.

중계 방식으로는 사내 AI 게이트웨이, 클라우드 사설 엔드포인트, 범정부 공통기반 경유가 있다. 공통기반을 경유하면 부서마다 중계 계층을 따로 짓지 않아도 되고, 이때는 A3공공 API 제공자도 함께 태그한다. 인증과 요청 상한을 걸었다면 S1AI 게이트웨이·단일 진입점도 기록한다.

상담 기록 요약이 망을 건너는 길

복지정책과 사례관리 담당자들은 긴 상담 기록을 요약해 회의 자료를 만드는 데 하루 몇 시간을 썼다. 로컬 오픈웨이트 모델로 시험해 보니 요약이 자주 가구의 위기 사정을 빠뜨렸고, 상용 모델의 결과가 확실히 나았다. 그러나 업무 PC는 행정망에 있었고 기록은 민감 등급이었다.

같은 시기 민원여권과의 한 직원이 인터넷망 PC에서 개인 키로 상용 모델을 부르는 도구를 쓰고 있다는 사실도 드러났다. 누가 무엇을 보냈는지 기록이 없었다. 정보통신과 AX팀은 두 문제를 하나로 풀기로 했다. 가람시 원칙에 따라 상용 모델은 A2.4내부망 프록시를 거칠 때만 허용하기로 했다.

AX팀은 기관 AI 게이트웨이를 세우고 허용 모델 목록을 등록했다. 요청은 먼저 C5가드레일 필터를 지난다. 이때 이름·주소·주민번호 같은 식별 정보가 가명으로 바뀐다. 게이트웨이를 통과한 호출은 C4감사 로그·지표에 남는다. 게이트웨이에 인증과 부서별 호출 상한을 걸어 S1AI 게이트웨이·단일 진입점도 겸하게 했고, 개인 키 호출은 막았다.

호출 기록이 한곳에 모이면서 부서별 사용량과 비용이 처음으로 한 표에 정리되었다. 게이트웨이에는 두 번째 상용 모델도 후보로 올려, 장애가 나면 넘어갈 자리를 만들었다. 지금 요청은 B1 → C5 → A2.4 (S1 겸함) → 상용 모델 · A2.4 → C4 순서로 흐른다.

장마철에 빗나가기 시작한 수위 예측

재난안전과는 3년치 하천 수위·강수 기록으로 수위 예측 모델을 직접 학습해 관제 화면에 붙였다. 첫 겨울과 봄에는 예측이 잘 맞았다. 그런데 장마가 시작되자 예측이 실측보다 계속 낮게 나왔다. 모델을 만든 직원은 이미 다른 부서로 옮겼고, 관제 서버에 어떤 모델 파일이 올라가 있는지도 확실하지 않았다.

AX팀은 모델을 A2.5비LLM 학습 모델 변형으로 서빙 계층에 다시 올렸다. 관제 화면의 예측 부품(B2예측·추천기)은 서빙 계층에서 위험 등급과 점수만 받는다. 서빙 계층은 모델 버전과 입력 분포의 변화를 C4감사 로그·지표에 남겨, 장마철처럼 분포가 학습 때와 달라지면 경고가 뜨게 했다.

재학습은 C6환류 파이프라인이 맡는다. 새 기준선으로 학습한 버전은 C9평가 세트·회귀시험의 독립 시험세트에서 이전 버전을 넘을 때만 배포된다. 넘지 못하거나 운영 중에 문제가 생기면 이전 안정판으로 돌아간다. 관제 요원이 예측 근거를 확인할 수 있도록 주요 변수의 기여도도 F9판정 근거·기여도 표시로 화면에 띄웠다. 관제 쪽 배선은 A1 → A2.5 → B2 → C1 · A2.5 → C4 · C6 → A2.5 · C9 → A2.5 · A2.5 → F9로 정리되었다.

이듬해 장마 전에 재학습한 버전이 게이트를 통과해 배포되었다. 모델을 만든 직원은 떠났지만 버전 기록과 재학습 절차는 남았다. 다음 담당자는 서빙 계층의 이력만 보고 어떤 판이 언제 왜 바뀌었는지 안다.

재난안전과는 공원 산책로에 쓰러짐을 감지하는 지능형 카메라를 도입했다. 제안서에는 감지 정확도 95%가 적혀 있었고, 시범 운영 결과 보고서에도 같은 숫자가 그대로 옮겨졌다. 정보통신과 AX팀이 보고서를 검토하다가 이 숫자를 어디서 쟀는지 물었다. 가람시 현장에서 잰 값은 하나도 없었다.

모델은 장비 펌웨어에 묶여 있어 가람시가 바꾸거나 다시 학습할 수 없었다. 도입 문서에는 '자체 AI 모델'이라 적혀 있었지만 실제로는 A2.6벤더 블랙박스였다. 안티패턴 X15빌린 성과표에 그대로 들어맞는 경우였다.

AX팀은 모델 내부 대신 바깥을 통제하기로 했다. 야간·우천·역광 영상을 섞은 현장 평가 세트를 C9평가 세트·회귀시험으로 만들어 실측했더니 야간 정확도가 제안서보다 크게 낮았다. 시범 운영 기간 지표는 C4감사 로그·지표에 쌓고, 유지보수 계약에 펌웨어 모델 변경 시 사전 통지와 회귀 확인 절차를 넣었다. 장비가 멈추거나 오탐이 늘면 C7폴백 스위치가 순찰 강화 같은 수동 절차로 넘긴다.

01문제

부서마다 모델·벡터DB·프롬프트를 따로 만드는 '부서마다 챗봇'(X3)은 공유 데이터를 중간마다 손으로 내려보내는 prop drilling의 공공 버전이다. 범정부 AI 공통기반처럼 상위에 이미 있는 Provider를 쓰지 않으면 같은 기반을 기관마다 다시 만들고, 인가·검증 절차도 제각각이 된다.

맥락. 모델·공공데이터·법령 원문·개발 환경을 공공 플랫폼에서 가져올 수 있다면 어느 과제든 해당한다. §7.1 2단계 '기반 부품은 새로 만들지 말고 Provider에서 먼저 찾는다'가 바로 이 부품을 가리킨다. 유형 7(대조·점검)에서는 법령·기준 출처를 대는 필수 기반이다.

힘(forces) — 서로 당기는 요구

  • 공통 Provider 재사용 vs 기관 고유 요구 반영
  • 공공 API 가용성·갱신 주기 vs 서비스 신뢰성
  • 인가·검증 절차의 통제 vs 에이전트 루프의 병목(PAX 공공API 진단)

02해법

기반을 새로 만들기 전에 범정부 AI 공통기반(모델), 공공데이터포털·법령 API(데이터), 모두의 AI 실험실·공공 깃랩(개발·실험 환경)에서 먼저 찾아 소비한다. 인증은 GPKI·디지털원패스 같은 연합 신원(Federated Identity)으로 위임하고, 공공 API 응답은 출처·조회 시각과 함께 업무 부품에 넘긴다. 에이전트가 부를 수 있게 하려면 A8 MCP 서버로 감싸고, 결과를 재가공해 기준선으로 고정하면 A1을 더한다. 기관이 만든 도구는 공공 깃랩에 등재해 다음 기관의 Provider가 되게 한다.

03적용

  1. 필요한 기반(모델·데이터·코드·실험 환경)을 목록으로 만들고 공공 Provider에 있는지 먼저 찾는다.
  2. 사용 승인·인증 방식(연합 신원)을 확인하고 호출 주체를 정한다.
  3. API 응답에 출처·조회 시각을 붙여 업무 부품에 넘기고, 최신성 검증 주기를 정한다.
  4. 에이전트가 쓰게 하려면 A8로 감싸고, 재가공해 고정하면 A1로 기록한다.
  5. 기관이 만든 도구·코드는 공공 깃랩에 등재해 다음 기관의 Provider가 되게 한다.

점검 질문

  • 같은 기반을 기관 안에서 따로 만들지 않았는가
  • 공공 API 응답의 출처·조회 시각이 결과에 남는가
  • API 장애·변경 시 어떻게 되는지 답할 수 있는가
  • 만든 도구가 공공 깃랩 등에 등재되었는가

환경 조건. E1 행정망에서는 공통기반 경유(A2.4)와 함께 쓴다. 공공 API가 인터넷 필수면 폐쇄망 과제는 반입·동기화 경로를 따로 둔다.

적용 노트

공공데이터포털이나 법령 API를 부르는 개인 개발 도구가 PAX의 큰 몫을 차지한다. 그래서 PAX 564건 태깅에서 A3는 156건으로 A7 다음으로 많다. 공개 사례로는 범정부 공통기반 RAG 위에서 접수 문서를 배분하는 도구, 법령 API로 매일 최신성을 검증하는 도구, 시행일 스냅샷을 비교하는 도구가 있다.

공공 API는 바뀌고 멈춘다. 응답에 조회 시각을 남기고 최신성 검증 주기를 정해 둔다. 인터넷이 있어야 하는 API를 폐쇄망 과제에서 쓰려면 반입·동기화 경로를 따로 둔다. 에이전트가 직접 부르게 하려면 A8MCP 서버·호스트로 감싸고, 응답을 재가공해 고정하면 A1데이터 자산 서비스를 더한다.

연계 예정이라고 적힌 칸

A1데이터 자산 서비스로 내부 기준선을 만든 복지정책과는 위기가구 예측의 정확도를 더 올리고 싶었다. 가람시 기록만으로는 공과금 체납이나 건강 위기 같은 신호가 보이지 않았다. 계획서에는 외부 공공기관 두 곳의 자료를 '연계 예정'이라고 적어 두었지만, 실제로 받은 자료는 없었다.

중간 점검에서 정보통신과 AX팀은 시연 화면의 예측이 업체가 만든 표본 자료로 돌고 있다는 점을 짚었다. 과제는 실데이터 없이 시연만 되는 X6데모웨어의 문턱에 서 있었다. AX팀은 기술 구현을 멈추고 협약부터 진행하자고 했다. 제공 기관 한 곳은 개인 단위 원자료 제공에 난색을 보였다. 복지정책과는 동 단위 집계 수준으로 협의안을 바꿔 동의를 얻었다.

AX팀이 세운 A4데이터 연계 서비스는 공통 연계키를 정하고, 식별자를 C5가드레일 필터에서 가명키로 바꾼 뒤 자료를 결합한다. 원본·가명·제출용 자료와 키맵은 따로 보관하고, 결합 결과의 결합키·변수 정의서에는 내부 기준선과 같은 방식으로 버전을 붙였다. 최종 배선은 A4 → A1 → A2.5 → B2 → C1 · C5로 정리되었다.

협약을 맺은 날 가람시는 이 과제를 Ready로 기록하고 협약 갱신일을 운영 절차에 올렸다. 결합 뒤 첫 재학습에서 예측이 그동안 놓치던 위기가구 유형이 드러났다. 복지정책과는 그 유형을 현장 방문 우선순위 기준에 넣었다.

산책로 침수 경보가 늦던 이유

재난안전과는 하천변 산책로 여섯 곳에 카메라를 달고 침수 위험을 감지하는 시범 사업을 했다. 영상은 이동통신 회선으로 시청 서버에 올라가 추론되었고, 위험이 감지되면 관제 화면에 표시되었다. 비가 많이 오는 날일수록 회선이 불안정해 영상이 끊겼고, 화면에 경보가 뜨는 데 몇 초씩 걸렸다. 개인정보 담당자는 산책로 이용자의 얼굴이 담긴 영상이 하루 종일 전송된다는 점도 문제로 짚었다.

재난안전과와 정보통신과 AX팀은 추론을 현장으로 옮기기로 했다. 중앙 서버에서 학습·검증한 모델을 경량화해 현장 단말의 NPU에 올리는 A5엣지 추론 런타임을 택했다. 경량화로 떨어진 정확도는 C9평가 세트·회귀시험으로 재고, 중앙이 승인한 버전만 단말에 배포한다. 통신이 끊긴 곳은 점검 때 물리매체로 갱신한다.

현장 단말이 위험을 판정하면 A11액추에이션·현장 통지 어댑터가 경광등과 방송으로 바로 알린다. 원본 영상은 이벤트가 있을 때만 짧게 저장하고, 시청에는 이벤트 요약과 조치 기록만 C4감사 로그·지표로 보낸다. 단말 고장에 대비해서는 C7폴백 스위치가 해당 구간을 출입 통제 상태로 돌리는 Fail-safe를 두었다. 현장 쪽 조립은 A5 → B5 → C2 → A11 → D5 · A5 → C4 · C7 · C9 → A5 배선이다.

다음 장마철, 회선이 끊긴 날에도 현장 경보는 제때 울렸다. 중앙으로 가는 전송량은 이벤트 요약 분량으로 줄었다.

17세 자녀의 여권을 묻는 전화

민원여권과의 상담 도구는 여권 관련 규정 문서를 검색해 답하는 B3지식 접지 상담이었다. 일반 질문에는 잘 답했지만, 예외가 걸린 질문에서 자주 틀렸다. 17세 자녀의 여권을 묻는 시민에게는 일반 발급 요건만 안내하고 법정대리인 동의 서류를 빠뜨렸다. 병역 의무자의 국외여행 허가도 같은 식으로 놓쳤다. 검색은 질문과 비슷한 단어가 많은 조항을 가져왔을 뿐, 그 조항에 어떤 예외가 걸려 있는지는 몰랐다.

정보통신과 AX팀이 처음 한 일은 이런 관계 질문 50개를 C9평가 세트·회귀시험으로 모아 실패율을 재는 것이었다. 그다음 현행 규정 원문을 정본으로 삼아 개념과 관계를 추출하고, 사전 필터로 관계 판정 대상을 줄인 뒤 모델에 관계를 판정하게 했다. 담당 주무관이 병합 전에 관계를 검토했다. 이렇게 만든 A6지식그래프 서비스는 '여권 발급 → 예외 → 미성년자 → 필요 → 법정대리인 동의' 같은 경로를 질의 API로 내놓는다.

상담 도구는 벡터 검색 결과에 그래프 경로를 붙여 답하고, 근거 조문을 F1출처 표시로 보인다. 배선으로 적으면 A1 → A6 → B3 → F1 · C9 → B3이다. 관계 질문 세트의 실패율은 크게 줄었다.

남은 일은 규정이 바뀔 때 그래프가 뒤처지지 않게 하는 것이었다. 규정이 개정되면 같은 주에 그래프를 고치도록 운영 절차에 넣었고, 갱신은 민원여권과 주무관 한 명이 맡는다. 갱신할 때마다 관계 질문 세트를 다시 돌려 결과를 남긴다.

01문제

용역 발주는 요구 정의부터 납품까지 길고, 납품 후 작은 수정도 다시 계약해야 한다. PAX 564건 가운데 438건(78%)이 개인 개발(334건)과 커뮤니티(104건) 사례로, 현장에서 직접 만든 도구다(원장 사례 구분 기준). A7 자체 제작 환경 태깅은 320건(57%)으로 이와 다른 기준이다. 현장의 반복 업무를 가장 빨리 줄이는 길이 이 환경이다. 그러나 개인이 만든 도구는 라이선스·저장소·인수인계 없이 퍼져 담당자 이동과 함께 멈춘다(X9).

01문제

에이전트가 공공 API·업무 시스템을 쓰려면 매번 호출 코드를 따로 짜야 하고, 무엇을 읽고 쓸 수 있는지가 코드 속에 흩어진다. PAX 564건 태깅에서 A8이 붙은 사례는 95건(17%)으로, 이제 현장에 넓게 깔렸다. 도구 설명과 실제 권한이 어긋나는 문제(X7)도 그만큼 흔하다. PAX MCP 6축 검증(2026년 10월 14일 기준 93건)에서는 권한 표면 주의가 36건, 공급망 주의가 28건이었다.

02해법

공공 API·업무 시스템·로컬 파일을 도구 설명·인증·정책과 함께 MCP 서버로 감싸 에이전트에 노출하고, 호출 결과에 출처·갱신 시각을 붙이며 호출 로그를 남긴다. 읽기(P0) 서버와 쓰기(P2) 서버를 분리하고 C8로 도구별 실행 승인을 건다. 배포·등재 전에 PAX MCP 6축 검증(권한 표면·비밀·공급망·위생·인젝션·데이터 흐름)을 통과시키고 S11로 반입을 검사한다. 통과하지 못한 축이 있으면 전이 범위를 부서 공유 이하로 묶어 둔다. 도구 목록·버전·갱신 공지는 레지스트리(Service Discovery)로 관리한다. 폐쇄망에서는 로컬 모델(A2.2)로 여러 MCP를 돌리는 로컬 호스트 변형을 쓴다.

  1. 노출할 기능을 읽기(P0)와 쓰기(P2)로 나누고 서버를 분리한다.
  2. 도구 설명과 실제 권한이 일치하는지 확인하고 도구별 실행 승인(C8)을 정한다.

  4. PAX MCP 6축 검증과 S11 반입 검사를 통과시킨다.
  5. 레지스트리에 도구 목록·버전·갱신 공지를 올리고 실제 업무 호출 지표를 잰다.

점검 질문

  • 도구 설명이 '조회'인데 쓰기·실행 권한을 가진 도구가 없는가
  • 6축 검증 결과가 기록되어 있는가
  • 호출 로그와 실제 업무 호출 지표가 있는가

환경 조건. E3가 MCP·CLI 설정이면 §5에 따라 B3에는 'A8 서버가 코퍼스 제공', B6에는 'A8 + C8 읽기/쓰기 분리 + MCP 6축 검증'이 붙고, 공통으로 A8 레지스트리·버전·갱신 공지를 둔다. E1 폐쇄망의 B6은 A8 로컬 MCP 호스트와 A2 로컬 모델로 꾸린다. 신뢰할 수 없는 입력을 받으면서 권한이 P2 이상이면 S5 또는 S6에 S9를 더한다.

적용 노트

PAX 564건의 4축 평가에서 MCP 서버 역할로 판정된 사례는 80건(14%)으로 현장에 넓게 퍼졌다. 태깅 기준으로는 A8이 95건이다. 그러나 PAX MCP 6축 검증(2026년 10월 14일 기준 93건)에서는 권한 표면 주의가 36건, 공급망 주의가 28건이었다. 6축 검증에서 통과하지 못한 축이 있으면 전이 범위를 부서 공유 이하로 둔다(§12).

Gulli(10장)는 MCP를 도구·자원·프롬프트를 동적으로 찾아 쓰게 하는 개방형 클라이언트-서버 표준으로 설명한다. 기존 서비스를 MCP로 감싸면 다시 짜지 않고 재사용한다는 것이 그의 요지다. 그는 단서도 붙인다. 서버가 돌려주는 데이터는 에이전트가 읽는 형태여야 하며, 원본 PDF를 그대로 넘기면 감싼 효과가 없다. 공공 API를 감쌀 때 응답을 텍스트·표로 정리해 넘기는 것도 같은 이유다.

도구 출력은 신뢰할 수 없는 입력이다. 쓰기 권한(P2 이상)이 있는 호스트가 외부 도구 출력을 읽으면 S6격리 LLM·맵리듀스 같은 S 부품을 함께 둔다(신뢰 불가 입력 규칙). 폐쇄망에서는 로컬 모델(A2.2주권형 온프레미스)로 여러 MCP를 돌리는 로컬 호스트 변형을 쓴다. 표준 시스템에 API가 열리면 브라우저 위에 덧씌운 B8레거시 오버레이를 이 부품으로 대체한다.

조회 전용 서버의 예약 취소 버튼

가람시의 한 공무원은 공공시설 목록과 예약 현황을 에이전트가 조회하는 MCP 서버를 개인적으로 만들어 동료들과 나눠 썼다. 반응이 좋자 그는 편의를 위해 예약 취소 도구를 같은 서버에 덧붙였다. 서버 설명에는 여전히 '조회 전용'이라고 적혀 있었다.

정보통신과 AX팀이 기관 도구 목록에 이 서버를 올리려고 PAX의 MCP 6축 검증을 돌리자 권한 표면 항목이 먼저 걸렸다. 설명과 실제 권한이 어긋난, 안티패턴 X7도구 설명 ≠ 실제 권한 그대로였다. 에이전트가 시민 문의를 처리하다 예약을 잘못 취소해도 막을 장치도, 남는 기록도 없었다.

AX팀과 제작자는 서버를 둘로 나눴다. 조회 도구만 담은 읽기 서버는 결과에 출처와 갱신 시각을 붙인다. 예약 취소를 담은 쓰기 서버는 C8권한 경계·킬스위치의 도구별 실행 승인을 거쳐야만 동작한다. 두 서버의 호출은 C4감사 로그·지표에 남는다. 등재 전에는 S11인제스천·공급망 검증으로 의존 패키지와 비밀 노출을 검사한다. 정리된 배선은 A8 → B6 → C8 → C4 · A8 → F1 · S11 → A8이다. 6축을 모두 통과한 뒤에야 서버는 부서 공유를 넘어 기관 도구가 되었다.

레지스트리의 성과 칸에는 서버 개수 대신 월별 실제 업무 호출 수를 적는다(X8). 서버를 만든 공무원은 그 뒤로 도구를 하나 보탤 때마다 읽기인지 쓰기인지부터 정한다.

01문제

업무 규범이 담당자 머릿속이나 개별 프롬프트에 흩어져 있으면 같은 질문에도 출력 품질이 들쭉날쭉하고, 모델을 바꾸면 규범도 사라진다. 모델을 바꾸거나 규범을 재사용하려면 규범을 코드·모델 밖으로 빼 두어야 한다. PAX에서 AI-Enabled로 판정된 171건 중 35건이 A9를 쓴다.

맥락. 기안·보고서·콘텐츠처럼 서식과 문체가 정해진 산출물을 만드는 B1·B7, BYO 코딩 에이전트 환경(E2 모델 중립), 개발 코파일럿에서 쓴다. 유형 4·6·12에서는 필수 기반이고, §7.2 진행 경로에서는 3단계에 놓인다.

힘(forces) — 서로 당기는 요구

02해법

규정집·매뉴얼·서식 예시에서 업무 규범을 뽑아 지침(구조·문체·금지 사항), 검증기(형식·인용·수치 검사), 출력 서식(HWPX·DOCX 등)으로 묶은 스킬 패키지로 만든다. 모델 호출 코드와 분리된 파일로 두어 어떤 코딩 에이전트·모델에서도 같은 절차가 돌게 한다(External Configuration). 산출·검증된 수치와 출처만 주입하고 미제공 수치·순위 생성을 금지하는 식으로 생성 범위를 규범으로 좁힌다. 스킬은 버전으로 관리해 규범 유출·변경을 추적하고, C9로 스킬 변경 전후 품질을 잰다.

03적용

  1. 대상 산출물의 규범(구조·문체·서식·금지 사항·검증 규칙)을 규정집·우수 사례에서 뽑는다.
  2. 지침·검증기·출력 서식으로 나눠 모델 호출 코드 밖 파일로 패키징한다.
  3. C9 평가 세트로 스킬 적용 전후 출력을 비교한다.
  4. 스킬을 버전으로 관리하고 변경 이력을 남긴다.
  5. 라이선스를 명시해 공공 깃랩 등으로 배포하고 타 기관 재사용을 연다.

점검 질문

  • 규범이 모델 호출 코드와 분리된 파일로 있는가
  • 검증기가 출력 형식·인용·수치를 실제로 검사하는가
  • 스킬에 버전이 있는가
  • 다른 모델로 바꿔도 같은 서식이 나오는지 확인했는가

환경 조건. E2 BYO·E3 AI 도구 설정이 전형이다. §5에 따르면 E1 로컬 PC 완결 B1에는 'A9 스킬 + A10 어댑터'가 붙고, E2 BYO의 B6·B1은 A9 스킬 형태로 배포한다. 이때 MIT·Apache 라이선스 명시가 전이 조건이다.

적용 노트

PAX 564건 태깅에서 A9는 54건이다. 그 54건 가운데 35건(65%)이 4축 평가에서 AI-Enabled로 판정되었다. 보고서 구조 스킬, 카드뉴스 스타일 스킬, 인용 검증 스킬, PDF 규정집을 스킬로 바꾸는 도구까지 모양이 제각각이다.

Gulli는 부록 A에서 역할·시스템 프롬프트, 구분자, 구조화 출력, 몇 개의 예시를 주는 few-shot을 되풀이해 쓰는 기법으로 정리한다. 업무 규범 스킬은 그 기법을 담당자 개인의 요령으로 두지 않고 기관이 관리하는 파일로 고정한 것이다.

BYO 환경에서는 모델을 바꿀 수 있다는 사실 자체가 대체 경로가 되므로, A9가 사실상 C7폴백 스위치의 역할을 겸한다. 산출·검증한 수치와 출처만 주입하고, 주어지지 않은 수치·순위는 만들지 못하게 하는 식으로 생성 범위를 규범으로 좁히면 환각 위험도 줄어든다. 갱신이 잦은 규범은 A2.3튜닝형으로 가중치에 넣지 말고 스킬로 주입한다.

담당자마다 다른 답변 초안

민원여권과는 민원 답변 초안을 쓰는 B1코파일럿을 도입했다. 몇 주 뒤 과장이 결재 문서를 보다가 이상한 점을 발견했다. 같은 유형의 민원인데 담당자마다 답변의 구조가 달랐고, 어떤 답변은 근거 조항을 빠뜨렸으며, 어떤 답변에는 지침에서 쓰지 말라고 한 표현이 들어 있었다. 담당자들이 각자 만든 프롬프트를 쓰고 있었기 때문이다.

AX팀은 우수 답변 사례와 민원 처리 지침에서 규범을 뽑아 A9업무 규범 스킬로 묶었다. 지침에는 답변 순서(요지 → 근거 조항 → 처리 결과 → 안내), 문체, 금지 표현을 적었다. 검증기는 인용한 조항이 실제 근거 목록에 있는지, 필수 항목이 빠지지 않았는지 검사한다. 출력 서식은 A10문서 형식 어댑터를 거쳐 공문 답변 양식으로 나간다. 스킬은 모델 호출 코드와 분리된 파일이라, 기관이 모델을 바꿔도 그대로 쓴다.

스킬을 고칠 때마다 C9평가 세트·회귀시험의 민원 60건으로 전후 답변을 비교해, 새 규칙이 다른 유형의 답변을 망치지 않는지 확인한다. 답변 한 건이 지나는 경로는 A9 → B1 → A10 (HWPX) → C1 → D8.3 · C9 → A9이다.

스킬 파일에는 버전과 변경 이력을 붙였다. 어느 판의 규범으로 쓴 답변인지 나중에도 가려내기 위해서다. 이웃 시의 민원 부서가 이 스킬을 달라고 했을 때 AX팀은 기관명만 바꿔 넘겼다.

24개 부서 요구서를 복사하던 사흘

기획예산과는 해마다 24개 부서의 예산 요구서를 받아 쟁점을 요약하고 심의 자료를 만든다. 요구서는 HWPX 문서였고, 부서마다 표 구성이 조금씩 달랐다. 요약 도우미를 도입했지만 도우미는 HWPX 파일을 읽지 못했다. 담당자가 본문을 복사해 붙여 넣으면 표가 한 줄로 뭉개지고 각주가 본문에 섞였다. 요약 결과는 다시 심의 자료 서식에 손으로 옮겨야 했다. 사흘이 걸렸다.

새로 만들기 전에 AX팀은 공공 깃랩과 공개 도구에서 HWPX 파서부터 찾았다. 쓸 만한 공개 라이브러리를 바탕으로 A10문서 형식 어댑터를 두 방향으로 구성했다. 입력 파서는 요구서의 항목 구조와 표를 보존해 구조화 텍스트와 표로 바꾼다. 출력 쪽 서식 생성기는 A9업무 규범 스킬에 정리한 심의 자료 서식대로 HWPX 기안을 만든다. 요구서에는 미확정 사업이 섞여 있어 변환은 모두 담당자 PC 안에서 한다.

지난해 요구서 20건을 C9평가 세트·회귀시험으로 삼아 표 변환 정확도를 재고, 병합 셀이 많은 서식에서 틀리는 부분을 고쳤다. 결과물은 C1검토 큐에서 담당자가 확인한 뒤 결재에 올린다. 취합 한 번이 지나는 경로는 A10 → B1 → A10 (HWPX 출력) → C1 → D8.5이다.

사흘 걸리던 일은 반나절로 줄었다. 병합 셀 문제를 고친 파서는 공공 깃랩에 올려, 다음에 HWPX 파서를 찾는 기관이 처음부터 만들지 않게 했다.

아무도 보지 않던 새벽의 경보

재난안전과의 하천 수위 감지는 잘 작동했다. 문제는 그다음이었다. 어느 새벽 상류에 비가 집중되자 감지 모델이 수위 급상승을 판정했지만, 판정은 관제 화면에만 떴다. 야간 관제실은 비어 있었고, 순찰에서 돌아온 직원이 40분 뒤 화면을 보고서야 산책로를 통제했다. 다행히 이용자는 없었다.

정보통신과 AX팀은 판정이 화면 밖으로 나갈 길을 만들기로 했다. C2위험도 라우터가 판정을 주의·경계·위험 등급으로 나누면, A11액추에이션·현장 통지 어댑터가 등급별 채널로 내보낸다. 위험 등급은 산책로 경광등과 방송을 자동으로 켜고(A11a), 경계 이상은 당직자와 담당 팀장에게 푸시와 문자를 보낸다(A11b). 300초 안에 처리 상태가 바뀌지 않으면 다시 알리고 상위 책임자에게 올린다.

물리 설비를 자동으로 켜는 만큼 권한 축은 P2a로 기록했다. 오탐으로 방송이 나가면 관제 요원이 C8권한 경계·킬스위치로 즉시 끄고, 장비 이상 때는 안전 상태로 전환한다. 발송·처리 상태·반응 시간은 C4감사 로그·지표에 남고, 오탐 기록은 등급 기준을 고치는 데 쓴다. 판정에서 경보까지는 A5 → B5 → C2 → A11 → D5 · A11 → C4 · C8 배선으로 이어진다.

첫 달에 오탐 방송이 두 번 나갔다. 그 두 건의 기록을 근거로 위험 등급의 기준 수위를 조정했다.

02해법

업무 부품의 입출력 앞뒤에 모달리티 변환 층을 두어, 음성·시야·다국어 입력을 텍스트로 바꾸고 텍스트 출력을 음성·자막·번역·아바타 발화로 바꾼다. 업무 로직은 텍스트 기준으로 유지하고 변환 층만 채널별로 교체한다. 번역·쉬운 언어 변환처럼 의미가 바뀔 수 있는 출력에는 날짜·숫자·금액 같은 확인 필요 항목을 표시하는 C5 가드레일과 F7 한계 안내를 붙인다. 현장 기기에서 돌려야 하면 A5와 함께 조립한다.

03적용

  1. 대상 이용자와 접점(창구·전화·현장·키오스크)을 정하고 필요한 모달리티를 고른다.
  2. 업무 로직은 텍스트로 두고 입출력 변환 층만 채널별로 붙인다.
  3. 번역·쉬운 언어 변환 출력에 확인 필요 항목 표시(C5)와 한계 안내(F7)를 붙인다.
  4. 현장 기기나 폐쇄 현장이면 A5와 함께 로컬 처리로 구성한다.
  5. 변환 오류(인식률·번역 오류)를 C4에 기록해 개선한다.

점검 질문

  • 텍스트 외 접근 경로가 최소 하나 있는가
  • 변환 과정에서 숫자·날짜·기관명 오류를 확인하는 장치가 있는가
  • 변환 결과의 한계가 이용자에게 안내되는가

환경 조건. E3는 모바일 앱·웨어러블(R8)인 경우가 흔하다. 폐쇄 현장이면 온디바이스 음성 생성처럼 A5와 함께 로컬 완결로 구성한다. 음성·시야 입력은 E5 S 이상이 되기 쉽다.

적용 노트

A12는 v0.6에서 A10문서 형식 어댑터와 대칭을 이루는 사람 쪽 어댑터로 신설되었고, 카탈로그 등재 상태는 후보다. PAX 564건 태깅에서는 13건이고, 그중에는 로컬 네트워크 안에서 다국어 음성 생성·전송을 끝내는 사례가 있다.

음성·시야 입력은 데이터 등급이 민감 이상이 되기 쉽다. 폐쇄 현장이나 착용 기기에서 돌려야 하면 A5엣지 추론 런타임과 함께 로컬 완결로 구성한다. 변환 층은 한 번 만들면 여러 대민 서비스가 함께 쓰므로 범정부 탑재 후보다.

창구 앞에서 돌아선 사람들

민원여권과는 창구 대기 시간을 줄이려고 대기석 태블릿에 여권 민원 상담 도구를 놓았다. 젊은 민원인은 잘 썼지만, 작은 글씨를 읽기 어려운 고령 민원인, 한국어가 서툰 외국인 주민, 화면을 볼 수 없는 시각장애인은 결국 창구 직원을 기다렸다. 상담 도구가 텍스트 화면만 전제하고 있었기 때문이다.

상담 로직은 손대지 않았다. AX팀은 그 앞뒤에 A12접근성·모달리티 어댑터를 붙였다. 입력 쪽에서는 음성을 텍스트로 받아 적고(STT), 외국어 질문을 번역한다. 출력 쪽에서는 같은 답변을 음성으로 읽어 주고, 자막과 큰 글씨, 다국어, 쉬운 언어로 바꾼다. 상담 로직(B3지식 접지 상담)은 여전히 텍스트 하나만 다룬다.

번역과 쉬운 언어 변환은 의미가 바뀔 수 있다. 그래서 수수료·유효기간·발급일 같은 날짜와 금액에는 C5가드레일 필터가 '창구에서 확인 필요' 표시를 붙이고, 화면과 음성 끝에 번역 한계를 F7한계·신뢰도 안내로 알린다. 인식 실패와 번역 오류는 C4감사 로그·지표에 남겨 매달 고친다. 창구 상담 한 건은 A12 (STT) → B3 → A12 (TTS·자막) → D7 · C5 · F7 · C4 경로를 오간다.

같은 변환 층은 복지 상담 창구에도 그대로 붙었다. 대기석에서 창구로 넘어오는 단순 문의가 줄면서, 창구 직원은 서류 확인처럼 사람이 해야 하는 일에 시간을 더 쓰게 되었다.
